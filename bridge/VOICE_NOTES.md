# Voice integration findings

Checked 2026-11-15 against the locally installed Codex CLI `0.169.0-alpha.11.1` and current official documentation. The initial subscription-only probe used no API credential. A later authorized API-key integration verified model access and minted an ephemeral Realtime client secret, without logging or exporting the long-lived key. No microphone input was captured during those backend probes.

The experimental app-server JSON schema generated by the installed binary includes `thread/realtime/start`, `appendAudio`, `appendText`, `appendSpeech`, `stop`, and `listVoices`. It describes audio chunks, output audio/transcript events, WebSocket and WebRTC transports, voice selection, and coordination with a backing Codex thread. These are experimental methods; their presence alone does not establish account access.

A local app-server initialized with experimental APIs enabled and successfully listed voices. A temporary, ephemeral, read-only thread then requested an audio session over the WebSocket transport, with host execution tools disabled. Startup returned an acknowledgement but immediately emitted `thread/realtime/error` with the message **“realtime conversation requires API key auth.”** The probe stopped the session and process. This establishes that this installed runtime/account combination does not provide subscription-only realtime audio through that route; it does not prove that all future versions or account configurations will behave identically.

The native fallback path is iPad-native speech recognition → text and canvas context → subscription-authenticated Codex process → validated canvas operations and text reply → iPad system speech synthesis. This can maintain a hands-free conversational interface while keeping the existing subscription connector. Its latency, interruption behavior, and voice differ from OpenAI's speech-to-speech service. Account and settings screens should describe that distinction plainly.

Official references:

- [Codex app-server](https://learn.chatgpt.com/docs/app-server) documents the local agent integration and account interface.
- [ChatGPT plan usage preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) excludes audio/video input and the transcription API from that separate token-sharing flow. Do not assume that text access grants voice access.
- [Voice WebRTC guide](https://developers.openai.com/api/docs/guides/voice-webrtc) describes the API-backed voice route and server-held API credentials. It documents the separate API-backed integration now supported by the companion.

These findings informed original integration code. No external implementation or generated schema is included in the project source.

## API-backed Realtime

The optional API route uses the official `/v1/realtime/client_secrets` endpoint and a fixed `gpt-realtime-2` session. The user-authorized key remains in its existing private file on the Mac; a separate private state configuration references that path. The paired iPad receives only `{token,model,expiresAt}` with a60-second connection deadline. Status responses contain readiness/model metadata only. Redirects are disabled; raw provider error bodies, tokens, key paths, and keys are never logged or returned as errors.

Live checks confirmed model access and successful session-credential minting with PCM24k mono with input transcript events from `gpt-4o-mini-transcribe` input/output, `marin`, server voice activity detection, interruption, and two function tools. A native macOS URLSession WebSocket probe received session.created and both expected function-call payloads: immediate green-triangle editing and a queued raster-image task. The image job was not executed. A second probe streamed a synthetic spoken command as40ms PCM chunks; it received an input transcript and a valid blue-circle edit payload. These verify API transport and speech-to-tool routing; actual microphone/speaker quality, interruption, and iPad behavior still require device testing. API charges/limits are separate from subscription canvas generation. Configuration readiness does not continuously verify billing or key validity.

`edit_canvas` applies at most24 simple native operations after native validation. `submit_canvas_task` immediately queues a longer canvas job; its completion is delivered later, so conversation can continue. Simple y=f(x) graphs use native rendering; 3D, phase portraits, differential equations and implicit plots use original self-contained widgets through the longer-task route, with numerical limits described honestly. The voice model does not have arbitrary Mac tools.

Official protocol references: [ephemeral client secrets](https://developers.openai.com/api/reference/resources/realtime/subresources/client_secrets/methods/create) and [Realtime WebSocket events](https://developers.openai.com/api/docs/guides/realtime-websocket).
